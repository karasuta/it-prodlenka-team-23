# Шаблон проекта для хакатона ( serverless )

Рабочий каркас: **FastAPI**-бэкенд, **Vite + React**-фронтенд (одностраничное приложение, Feature-Sliced Design) и **YDB**. Локально всё запускается одной командой. В облако код выкатывается через SourceCraft CI/CD в ваш каталог Yandex Cloud: бэкенд работает в Cloud Function, фронтенд лежит в Object Storage, снаружи всё доступно через один API Gateway. Ресурсы в облаке CI создаёт сам.

Сейчас в шаблоне одна страница. Она запрашивает у бэкенда `GET /api/hello` и показывает ответ: приветствие (слово Hello — ссылка на сам эндпоинт) и состояние базы YDB (бэкенд выполняет `SELECT 1`). Там же ссылка на документацию API. Всё остальное пишете вы.

Документы хакатона:

- [HACKATHON.md](HACKATHON.md) — о мероприятии: расписание, роли в команде, организационные моменты;
- [CASE.md](CASE.md) — задача: персональный AI-маршрут по Пушкинскому музею;
- [TEAM.md](TEAM.md) — карточка команды и описание решения, заполните её до финального питча.

## Главный принцип

**Простое лучше сложного.** За архитектурную сложность на хакатоне баллов не дают. Тратьте время на идею, а не на инфраструктуру. Те же правила записаны в [`AGENTS.md`](AGENTS.md), и AI-ассистент следует им.

## Структура

```
backend/                 FastAPI, Python 3.12, uv (в облаке — Cloud Function)
frontend/                Vite + React + TypeScript + Tailwind, FSD (слои в frontend/src)
deploy/api-gateway.yaml  спецификация API Gateway
.sourcecraft/ci.yaml     CI/CD: тесты, сборка, создание ресурсов и деплой
.env.template            переменные для локального запуска с комментариями
AGENTS.md                инструкции для SourceCraft Assistant
```

## Локальный запуск

Нужны только **Docker** (Docker Desktop на macOS и Windows) и **git**.

```bash
cp .env.template .env
docker compose up -d
```

Откройте http://localhost:5173/: на странице будет сообщение от бэкенда.

- Первый запуск занимает несколько минут: собираются образы и стартует YDB.
- Код в `frontend/src` и `backend/app` перезагружается автоматически, перезапускать контейнеры не нужно.
- Запросы на `/api/...` dev-сервер Vite передаёт бэкенду, как API Gateway в облаке. Поэтому фронтенд всегда ходит на относительный `/api`.
- После добавления зависимостей (`uv add ...` в `backend/`, `npm install ...` в `frontend/`), а также после правки конфигов (`vite.config.ts`, `package.json`, `index.html` и т. п.) пересоберите контейнеры: `docker compose up -d --build`.
- Документация API: http://localhost:5173/api/docs. Веб-интерфейс YDB: http://localhost:8765.
- В логах бэкенда при старте есть строка `YDB connection succeeded` или `YDB connection failed`.
- Чтобы бэкенд обращался к модели AI Studio, укажите в `.env` `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` (модель задаёт `YANDEX_MODEL`). Тогда на главной странице появится ответ модели на демо-вопрос, а в `/api/docs` заработает `POST /api/ai/ask`. Без этих переменных приложение работает, только карточка LLM показывает «not configured».
- **Windows:** держите репозиторий внутри файловой системы WSL2 (например, `~/projects`, а не `/mnt/c/...`). Иначе автоперезагрузка работает медленно.
- Порты 5173 и 8765 не должны быть заняты на вашем ноутубке другими приложениями.

Как запустить без Docker (для отладки; нужны [uv](https://docs.astral.sh/uv/) и Node.js 22):

```bash
cd backend && uv sync && uv run pytest                                # тесты бэкенда
cd backend && uv run uvicorn app.main:app --port 8000                 # бэкенд без YDB
cd frontend && npm ci && npm run dev                                  # фронтенд на :5173
cd frontend && npm run build                                          # сборка в frontend/dist
```

## Деплой в облако

Как это устроено:

```
Браузер → API Gateway (https://<id>.apigw.yandexcloud.net)
            ├─ /api/*   → Cloud Function  (FastAPI)
            └─ всё иное → бакет Object Storage (index.html)
```

Фронтенд и API работают на одном HTTPS-домене, поэтому CORS настраивать не нужно. Свой домен не нужен.

Репозиторий команды и сервисное подключение уже подготовлены организаторами.
Войдите в SourceCraft под тем же аккаунтом, который получили для Yandex Cloud,
и откройте ссылку на свой репозиторий со страницы выдачи. Новый репозиторий создавать не нужно.

### Доступ команды

У всех семи выданных аккаунтов команды есть роль `developer` в этом приватном репозитории.
Клонируйте его под своим аккаунтом. Работайте в ветках и отправляйте готовые изменения в `main`.

### Подключение к Yandex Cloud

Подключение организации `it-prodlenka-ci-23` уже ограничено этим репозиторием
и сервисным аккаунтом каталога команды. В `.sourcecraft/ci.yaml` указаны его имя и `scope: repo`.
Ключи доступа для CI создавать и добавлять в репозиторий не требуется.
Подключение видно в **Настройках организации → Сервисные подключения**; список
в настройках репозитория показывает только подключения, созданные на его уровне.

### Запуск

CI запускается при изменении исходников в `main`. Загрузка организаторами
готового шаблона не запускает деплой. Чтобы развернуть проект без изменения
кода, откройте **CI/CD** этого репозитория и запустите workflow `deploy` вручную.
Результат и логи видны там же. Если прогон закончился ошибкой, обратитесь к организатору.

При каждом прогоне CI:

1. запускает тесты бэкенда, lint и сборку фронтенда: сломанный коммит не попадёт в облако;
2. создаёт базу YDB Serverless `hackathon-app-db`, если её нет (первый раз 1–2 минуты);
3. создаёт функцию `hackathon-app-api`, если её нет, и выкатывает новую версию (Python 3.12, 256 МБ, таймаут 60 с);
4. создаёт закрытый бакет `hackathon-app-<ID каталога>`, если его нет, и загружает туда `frontend/dist`;
5. создаёт или обновляет API Gateway `hackathon-app-gw` по `deploy/api-gateway.yaml`.

### 4. Адрес приложения

В логе последнего шага (`deploy-gateway`) есть строка `App URL: https://<id>.apigw.yandexcloud.net/`. Тот же адрес виден в консоли облака: **API Gateway → hackathon-app-gw → Домен**. На странице будет сообщение от задеплоенного бэкенда, статус YDB и ответ модели AI Studio с её именем. В облаке ключ AI Studio не нужен: функция авторизуется IAM-токеном сервисного аккаунта, а модель задаётся `YANDEX_MODEL` в `.sourcecraft/ci.yaml`. В логах функции (**Cloud Functions → hackathon-app-api → Логи**) должна быть строка `YDB connection succeeded`.

Когда ресурсы простаивают, они почти ничего не стоят: всё тарифицируется по использованию.

### Проверки перед деплоем

Первые шаги CI — `pytest` бэкенда (`backend-test-and-bundle`), lint и сборка фронтенда (`frontend-build`). Если любой из них упал, деплой останавливается и в облаке остаётся предыдущая рабочая версия. Причину смотрите в логе упавшего шага в разделе **CI/CD**.

Образец теста лежит в `backend/tests/test_hello.py`.

### Свои переменные окружения

Бэкенд читает настройки только из переменных окружения через `backend/app/config.py`. Локально значения берутся из `.env`, в облаке их передаёт в функцию CI.

**Несекретная переменная** (флаг, имя модели, адрес публичного API):

1. `backend/app/config.py`: добавьте поле со значением по умолчанию, например `page_size: int = int(os.getenv("PAGE_SIZE", "20"))`.
2. `.env.template`: добавьте `PAGE_SIZE=20` с комментарием.
3. Если значение в облаке должно отличаться от значения по умолчанию, добавьте его в `env` workflow `deploy` в `.sourcecraft/ci.yaml` (рядом с `YANDEX_MODEL`) и допишьте `,PAGE_SIZE=$PAGE_SIZE` в `--environment` шага `deploy-function`.

**Секретная переменная** (ключ стороннего API, токен) не должна попадать в репозиторий:

1. `backend/app/config.py`: `museum_api_key: str = os.getenv("MUSEUM_API_KEY", "")`.
2. `.env.template`: оставьте значение пустым (`MUSEUM_API_KEY=`), а настоящее впишите только в свой `.env`, который не коммитится.
3. SourceCraft: **Репозиторий → Настройки репозитория → Секреты → Новый секрет**, тип «SourceCraft», имя `MUSEUM_API_KEY`, значение — ваш ключ.
4. `.sourcecraft/ci.yaml`: в кубе `deploy-function` передайте секрет в `env` и допишьте его в `--environment`:

   ```yaml
   - name: deploy-function
     env:
       # ...
       MUSEUM_API_KEY: ${{ secrets.MUSEUM_API_KEY }}
     script:
       - |
         # ...
           --environment "...,YANDEX_MODEL=$YANDEX_MODEL,MUSEUM_API_KEY=$MUSEUM_API_KEY" \
   ```

- Значения не должны содержать запятых: `--environment` разделяет переменные запятой.
- Переменные окружения функции видны в консоли облака всем, у кого есть доступ к каталогу. Для каталога команды на хакатоне этого достаточно. Если нужна более строгая защита, храните секрет в Yandex Lockbox и передавайте его флагом `--secret` команды `yc serverless function version create`.
